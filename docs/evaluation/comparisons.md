# Registered comparisons

These are retained general-harness research requirements, not permission to
launch a study. Current whole-agent execution supports cold fresh seeded
natural tasks only; refusal of warm/restored/prepared/frozen/Jev conditions does
not implement those comparisons.

## Isolate learning from world memory

Practice creates reusable experience; comparison uses a snapshot frozen before
the batch; held-out starts never tune that snapshot, scoring or rehearsed tactics.
Keep hidden initialization identifiers evaluator-owned and opaque to actors.
Exposure remains recorded and requires different starts for a later unseen claim.

Each attempt resets conversation, summaries, workers/state, private artifacts,
world memory and outcome-bearing retrieval caches. Cold inherits no project
experience; warm gets only its exact immutable compatible snapshot. Both retain
the same bootstrap/programming/retrieval/optional-backend capabilities. Both may
adapt in a private branch, sealed from siblings and promotion until batch closure.

Match actual clean initial saves when supported. Otherwise disclose the reset/
initialization procedure and remaining variation; do not claim snapshot control.
Each copy gets new run/world lineage. Seed equality is not save equivalence.
Keep model/provider/settings, task/verifier, observation permissions/full config/
interface, game/adapter/capabilities, native mechanics/executor, server flavor/
build/effective Anti-Xray, helpers, references, entitlement and finite bounds fixed.
Changed permissions/helper tactics start another condition.

## Cold/warm procedure

1. Freeze the practice-derived warm library and compatible identities; cold's
   inherited snapshot is explicitly empty.
2. Prepare equivalent ordinary starts and freeze all settings above, task text,
   per-model startup limits and horizon equally across arms.
3. Predeclare repetitions and balanced order alternating first arm across pairs.
   Run serially on the same host; retain time/provider/resource variation.
4. Use normal product lifecycle and bounded model-private adaptation, with no
   tactical coaching, hidden feedback, state edits or privileged actor actions.
5. Stop on verified success, horizon, safety stop or terminal failure; retain
   last verified state/reason. Any extra diagnostic retains the original failure
   and is not a replacement sample.
6. Publish every scheduled attempt with pair/repetition, snapshot, objective,
   TTF plus same-window efficacy, policy acquisition/revision, progress,
   latency/idle, deaths, interventions and qualified usage/cost.

Use paired deltas where both endpoints exist. Keep censored/unmeasurable
outcomes; report all-scheduled and any narrower gameplay-only denominator with
exclusion reasons. Startup failures, outages and incomplete traces remain
classified outcomes. Recovery retains wall time/downtime and explicit rollback
branches/memory reconciliation. Publish warm-worse/indistinguishable results.
Small engineering samples establish no universal advantage.

## Required policy-capability experiment

At least one controlled research comparison uses two **cold** conditions:

| Condition | Capabilities |
| --- | --- |
| Policy-disabled control | Strategic tools, ordinary conditional/looping bounded programs, asynchronous executor, same permitted primitives; registered reactions and fast-policy requests disabled |
| JS/Jev-enabled treatment | All control capabilities plus declared model-authored registered JS and optional Jev policies under normal validation/trial/fencing |

Do not cripple control into one-action-per-model-turn or claim it cannot react.
Availability is treatment; retain actual authoring/trigger/use/revision, non-use,
unavailable Jev, failed/no-effect/unknown/regressing trials and task failures.

Freeze matched ordinary clean spawn saves, model/settings, verifier, profiles/
geometry permissions, server configuration, runtime/capabilities, primitives,
program interface/scheduling, reference access, auth conditions, startup/horizon
and comparable finite bounds. Predeclare sample/order and use the same sealed
lineage/evidence/censoring rules. Staged encounters/arenas cannot supply efficacy.

Compare control timing separately from progress/non-regression/deaths/success/
time-to-objective, retaining treatment acquisition and helper usage. The estimate
concerns the **policy-capability package**, not isolated Jev value or universal
novelty. Within-run version associations remain descriptive.

A treatment run can also be the cold/warm cold arm only if identical conditions
and reuse were predeclared: list the same run ID, never two independent samples.
Its matched policy-disabled arm is still required. JS-only/Jev-only/mixed or
async/serialized ablations are optional; serialized diagnostics must not replace
the shipped independent executor.
