# Research experience and promotion

For retained general-harness research, learning means model-authored external
knowledge/program/policy revisions used in later play, not weight training.
The ordinary local Java player is a separate developer-written system.
Callable interfaces belong to generated help and
[experience reference](../reference/experience.md); broader targets below are
not aliases for unimplemented tools.

Knowledge records facts/hypotheses, provenance, scope, confidence and supporting/
contradicting evidence. Skills record bounded procedures, exact dependencies,
preconditions/state/termination and actual invocations. Policies record bounded
reactive JS or typed fast-model configuration and trial/use evidence.
Documentation, prior knowledge, observation and inference remain distinguishable;
an unsupported model attribution is not a verified citation.

## Compatibility and isolation

Default reusable libraries are per strategic model and compatible game/adapter/
profile. A run pins an immutable snapshot before starting; sibling publication
cannot mutate it. Retain authoring model/provider as reported, source/config
hashes, parent, run/events, complete negotiated schema/profile/capability/build
identities, state format, dependencies, applicability, limitations and failed/
unknown/rejected/retired versions. No secrets/private reasoning/unrelated data.

Current executable compatibility uses envelope 3, payload schema/configuration,
native build/capabilities and API/validator/runtime5; the current descriptor uses
`minecraft_assisted_rgb_360_r8_control_v5`, payload
`minecraft_observation_v1@2`. Earlier schema2/r2/API1–4 remain read-only original
cohorts. Active validation/hydration checks actual registered schemas and the
built contract resource, not asserted hashes alone. Revalidation creates a new
immutable identity; dynamic boot/session/run/life/space fences do not change
reusable source compatibility.

Same-session `working_programs:"continue"` imports exact compatible definitions/
dependencies only for that session/model; `"fresh"` omits them. No args,
observations, worker state or stacks cross. `working_candidate` retention—even
with measured uses—is not cross-session qualification. Comparisons explicitly
exclude uncontrolled working definitions.

Reusable lessons can transfer only within declared compatible scope. Locations,
routes, encounters, maps and containers stay with legitimately observed world/
rollback lineage. Never relabel world data as general knowledge. Explicit
cross-model product imports preserve authorship and recheck applicability;
experiments never silently cross model/library partitions.

## Retrieval and promotion

Use bounded metadata/card/performance search before selective exact source.
Catalog latest versions remain distinct immutable snapshots; exact named loads
or latest-once resolution cannot silently overwrite payloads. Missing/
incompatible entries return explicit empty/rejected results, never substitutes.
A vector database is unnecessary.

Knowledge saves remain run-private until eligible promotion. Idempotent mutation
keys bind saves/proposals so lost acknowledgements create no duplicate versions.
The research target's promotion gate requires:

| Kind | Evidence floor |
| --- | --- |
| Knowledge | Immutable compatible scope, permitted provenance, confidence and authorized support/contradictions; documented facts can cite retained sources and inferences stay hypotheses |
| Skill/policy | Immutable admissible source, exact compatible dependencies, complete StrategyCard, no unresolved quarantine, permitted model-authored method and all conditions below |
| Startup bundle | Model-authored immutable selection/applicability; every included artifact/card/dependency independently eligible |

Programs need at least **one independently verified bounded real-gameplay use**
of the exact version, a real trigger, prospective intended-outcome predicate,
satisfying outcome and safety/non-regression evidence. Retain *all* failed,
unknown, no-effect and regressing history. Static validation/self-rating is
insufficient. One eligible use is **limited engineering evidence**, not
generalization. Unknown portability remains local; a parameterized revision needs
new scope and evidence.

Eligible proposals create a new immutable per-model snapshot without mandatory
human approval. Record exact source/card/evidence/conditions or rejection.
During sealed comparisons, defer publication until closure and reapply the gate;
never change a selected snapshot or expose sibling outcomes.

## Startup

Cold and warm get identical task/capability/backend/reference access. Cold removes
inherited experience, not programming. Host preflight owns readiness; the earlier
three-call/60-second bootstrap remains historical, not a current quota.

An eligible exact-version model-authored startup selection hydrates through
normal isolation/compatibility/freshness/fencing, with zero authoring calls
permitted. Cache validation only under matching source/runtime/isolation/
adapter/profile/schema/server configuration. No effects precede current
preconditions; missing/inapplicable entries visibly use ordinary authoring.
Log hydration/cache/rejections/activation/first effect separately from benefit.

The actual SDK supplement has a shared **32 KiB** serialized UTF-8 cap, at most
18 KiB source and 24 KiB help, not additive. Unknown-operation no-replay/custody/
confirmed-prefix constraints precede source/help; optional historical receipts
fit only afterward. Omission flags preserve partial evidence and cannot resolve
unknown effects or imply zero. Authorized inspection retains full detail.
