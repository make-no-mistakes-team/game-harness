# Revision evidence and StrategyCards

Runtime validity is not behavioral success. Policy lifecycle states and execution
statuses belong to [program reference](../reference/programs.md); validation
proves bounded admissibility/isolation, not tactical efficacy. An untested valid
candidate can enter a bounded real-play trial under the same information limits.

For each trigger/use retain observations, declared intent/preconditions, chosen
action, timing, actual consequence and subsequent game evidence. A policy never
triggered has no observed effectiveness rate. Local JS and real Jev are distinct;
backend failure/non-use remains explicit.

The model compares intended and observed effects, writes an immutable candidate/
card with hypothesis and parent evidence, validates/trials when admitted, then
selects activation/replacement/retirement under normal fences. Retain regressions
and quarantines. Restoring source is not restoring the world.

## StrategyCard

Each reusable program/policy pins an immutable versioned program/card pair:

| Required content | Meaning |
| --- | --- |
| Identity/source | Stable card/version/format, exact artifact kind/id/version and immutable source/config hash |
| Purpose | Intended gameplay outcome in plain language |
| Applicability/limits | Task/game/profile/capabilities, required observations/preconditions, world/portable scope and unknown/failure cases |
| Gameplay method | What it does and when, beyond an opaque name or code diff |
| Creation/revision reason | Hypothesis and opportunity/event/evidence refs; label retrospective explanations |
| Parent/semantic changes | Parent or explicit initial version; changes to method/preconditions/outcome and relevant unchanged constraints/reason |
| Evidence/outcomes | Exact trials/invocations/verifiers, conditions, opportunities/uses, sample sizes, failures/regressions and unknowns |

An empty evidence list means **untested/not yet measured**. Model explanations
are claims, not verified effects. Later evidence adds a linked card version;
changed source/config creates a new program version. Keep previous associations.
The required research improvement-history surface shows one actual change, why/
what changed and linked trial outcome or “not yet measured.” Display authorized
source as escaped inert text; no model script/markup executes in operator origin.
Do not expose hidden reasoning, secrets, privileged truth or another run's data.

## Acquisition metrics

Freeze a usefulness predicate before trial: real trigger, observable effect,
relevant latency/idle target and safety/non-regression. Only independently
verified real use establishes usefulness; inherited qualification or activation
alone cannot supply a zero current-run endpoint.

| Metric | Endpoint |
| --- | --- |
| `time_to_first_useful_policy_active_ms` | First running → first current-run verified useful outcome |
| `time_to_first_useful_policy_wall_ms` | Accepted start → same outcome, including startup/retrieval/downtime |
| `policy_creation_latency_ms` | First candidate-authoring request admission → `artifact.authored`, including attempts |
| `policy_validation_latency_ms` | Validation admission → completion; distinguish cache and failures |
| `policy_revision_latency_ms` | Opportunity delivered → linked revision authored, including waiting/deferral |
| `policy_activation_latency_ms` | Accepted activation → exact version effective, including fencing; rejected requests are not successes |
| `policy_revision_count` | Authored successors, excluding first versions/retries/card-only updates |
| `policy_trigger_opportunity_count` | Eligible opportunities per exact version, including no proposal |
| `policy_actual_use_count` | Executor-admitted proposals; confirmed/no-effect/rejected/expired/failed/unknown apart |

Retain opportunity/trial creation/update/delivery/decision, hypothesis, exact
program/card/parent, evidence window, validation, activation and disposition.
Open/censored endpoints remain not reached/unmeasurable with horizon, never zero.
Warm hydration/validation/activation/cache/first-effect records distinguish
retrieval, authoring, readiness and real benefit.

## Traces and descriptive comparisons

Bounded traces record actual APIs/results, authorized snapshots, instrumented JS
branches/source locations, intent, spans and omissions, not hidden reasoning.
Instrumentation preserves canonical source/hash and semantics. A branch or
`game.progress` statement proves neither motivation nor effect.

Use native action, dispatch/receipt/readiness, sandbox/capability wait, strategy,
scheduler and life-recovery spans with clock/overlap uncertainty. Compare actual
removals, own-inventory receipts, target ID/position switches and witnessed
travel/rotation. Extra excavation can enable legitimate access; target handles
alone do not identify trees or prove mistaken choices. Reported slow camera,
roughly five-second pauses and target-switch experience remain ground truth;
without exact evidence, causal explanations remain unknown.

Durable failure/death/outcome opportunities reach the same model. Exact-parent
inspection and candidate writes link source to feedback and experiment reason.
`keep`/`insufficient_evidence` assessments remain immutable but do not forbid a
later linked repair; no bookkeeping-only inference or mandatory pre-review.

Feedback V2 replaces/retracts published metrics with exact scope/version/
execution ordinal/revision/generation provenance. Scope removal is not global
deletion; moves atomically retract old and replace new scope. Retraction invents
no value; never-published removed executions emit nothing. Independent sequence/
scope hashes bind continuation. `has_more:false` does not erase pending source
work; inspection never advances publication.

Comparison V2 pins complete generations, versions and scope across pages/reopen,
before-side then after-side samples, including started/ended unknowns but not
undispatched cancellations. Missing/linkage/trace omissions remain explicit.
Changed versions are unmeasured until executed; measured before/after remains
`descriptive_only_no_causal_improvement_claim`, separate from promotion.
Whole-record omissions have recoverable references; retrieve complete authorized
generation-pinned records before claiming a complete population.

After verified success only one bounded effect-free review may author linked
candidates, with no extra gameplay trials. Optional bounded lookahead requires
fresh session/life/task/predecessor/source and readonly preconditions before
activation. Overlap and historical 31/13/7-call receipts prove no causal savings.
