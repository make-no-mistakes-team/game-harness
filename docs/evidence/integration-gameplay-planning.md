# Integration evidence: model-selected recovery, planning and revision

These were controlled technical experiments on the historical generic runtime,
not ordinary Survival efficacy or acceptance of later named-program interfaces.
Evaluator prompts/control conditions stayed part of each result.
Known cost was null; no causal speedup or experience promotion was established.

## Death recovery

Luna's controlled recovery passed in 105.40 seconds.
The evaluator forced death during an actual model-authored root movement.
The real DeathScreen retained 56 frames over 1,860 ms without automatic or
driver respawn. The model authored two first-version sources; its recovery
root explicitly requested vanilla respawn and performed a new-life action.
Run/world/session/native process and epoch 1 stayed the same while life 1→2
reached health 20. Cleanup closed, and the run-start inventory baseline stayed
unchanged. The observer stopped the run without verifier goal completion.

Usage was 15 requests / 15 messages, 63,370 uncached / 191,744 cache-read /
0 cache-write / 3,309 output. This was real model-selected recovery under
forced death, not ordinary-task success or a zero-provider fixture.

refusals. Request/message totals are not interchangeable with wire attempts.

The first attempt asked for lookahead twice after its root had closed.
The retained sequence was root start 18.823 s, turn end 18.890, root end
24.409, next main turn 24.524 and lookahead request 27.018.
Stale requests were correctly refused. Calls spent only on the former
`request_purpose_set` tool consumed context without gameplay/planning admission.
It was removed in favor of host scheduler/tool attribution; removal alone
does not prove fewer paid requests.

After optional start-time admission, the next repeat had exact
execution/source/request-linked API work inside independent inference.
The first stage failed predicate syntax at 1:16, and later speculative work
attempted forbidden `skill_start`. The invalid historical source was unavailable;
its location cannot prove a wrapper mistake. A forbidden call does not prove
the provider catalogue advertised it. Other work exhausted its finite allowance.

The copied-reference repeat captured placeholder/all-zero/wrong hashes and
`source_changed`, including a main-turn attempt after root closure.
Its predicates were valid bodies; that does not explain the earlier syntax
failure. The subsequent cutover removed redundant caller hashes and let the
host pin exact immutable ID/version/source/dependency identities; it did not
accept incorrect digests or weaken fresh guards.

The host-pinned repeat repaired an unescaped apostrophe **within the same
plan's remaining budget**, then staged and began fresh validation.
Its predicate compared session identity with `context.task.session_id`,
although `context.task` was a string. False evaluation was correct.
Three no-runnable-work turns ended the attempt while health remained 20.
Staging and validation were observed despite overall failed acceptance.

The next Luna plan selected 20 seconds after a five-second delay, leaving only
0.86 seconds between predecessor closure and expiry.
Two all-zero plan IDs preceded the real ID arriving too late.
Expiry correctly prevented validation/activation. An additional DTO-field
error in its predicate was never evaluated and is not a proven failure cause.
No budget relaxation or engine patch followed.

The separately authorized Sol control retained the same scenario,
**30-request/five-minute bounds and no automatic rerun**.
It passed the **old** interface with predecessor work during inference,
staging, fresh validation, explicit main activation and follow-up.
Cleanup closed; the custom goal stayed unverified. It did not erase the
failed Luna attempts or establish useful gameplay, promotion or acceptance
of the later named-program cutover.

## Revision experiments

The first revision attempt authored v1→v2 on the same ID, parent 1, distinct
hashes and canonical lines 35→43. Both roots succeeded with one neutral look
and two observations each. The comparison had one sample per version only.
It failed durable resolution linkage: `insufficient_evidence` was paired with
a revision, violating the existing revise-only invariant; a generic
`backend_unavailable` hid that domain error. Later resolutions had null revision.
Usage was 30 requests / 29 messages, 197,734 uncached / 585,344 cache-read /
3,179 output.

The correction returned typed `invalid_request`, preserving the invariant.
A real Luna retry passed complete authored-version/execution/comparison/decision
linkage in 92.87 seconds, with exact parent 1, distinct hashes and two successful
roots. Usage was 16/16, 115,769 uncached / 269,056 cache-read / 0 cache-write /
2,132 output. Cleanup closed, no source/predicate was injected, and no synthetic
Agent supplied the decision. The observer stopped it without verifier completion;
there were zero promotions. One sample per version remains descriptive.
The failed-link attempt stays failed; neither result proves improved Survival.

Actual comparison UI inspection showed exact hashes, source/card differences,
one sample/version and descriptive qualification at 1440×900 and 1000×650.
An offscreen helper click timed out without invoking Start world; scrolling
corrected the probe without changing the app.
Normal GNOME close exited 0 and closed game/API ports. This was one normal-close
observation, distinct from diagnostic X11 window destruction.
