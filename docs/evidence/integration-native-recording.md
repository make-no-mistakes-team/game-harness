# Integration evidence: capture, timing and replay

These are bounded zero-provider technical proofs with confirmed cleanup,
not autonomous Survival or model vision tests.
Retaining every **delivered** frame does not mean retaining every native render.
Audio was absent; structured observations and pixels were not proven synchronized.
See the ongoing [capture contract](../reference/capture.md).

## Short native recording

The first standalone proof retained 123/123 delivered frames as PNGs.
Expected replay duration was 4,097 ms; actual 4,160 ms, a 63 ms difference within
the predeclared 134 ms tolerance. Maximum capture gap was 51 ms.
Alive/death-menu/respawn images and a six-frame movie grid were inspected.
The clip preserved a deliberate 1,600 ms wait and 1,400 ms menu hold.
Interrupted motor receipt was cancelled/neutralized; later diagnostics showed
neutral inputs, inactive motor and no action motion.
It ended normally without an OS signal, so it did not prove SIGINT or Runtime Stop.

The GHV2 continuation repetition retained 132 frames.
Replay 4,480 ms versus expected 4,414 ms met the same 134 ms tolerance.
Inspected images showed real world, death menu and explicit respawn.
The compiled renderer also showed the real 1280×720 stream through WebGL.
Neither clip established strict-visual perception, live model vision or FPS.

## Control-window timing, 29 October 2026

The eight-case GHV2 continuation repetition retained 385 request timing samples
without missing/invalid/omitted rows, 16 source timing events and actual startup/
cleanup spans for 12 worker executions.
Fifteen successful movement intervals joined native key samples to their
operation, request and native clock.

Partitioning a 56.374-second control window left 2.747 seconds overlapping and
29.445 seconds unattributed. Neither amount was measured idle.
A separate recorder-process window identified its deliberate 1.600-second
wait without subtracting across processes.
The first complete SDK SSE event was observable; raw network first byte was
not. This instrumentation proved no pause reduction or ordinary attack/use
fidelity by itself.

## Thirty-minute profile proof, 30 October 2026

Explicit evidence-profile admission preceded native preparation; the retained
manifest recorded effective bounds, bytes, pending peaks and incomplete states.
The controlled sample wrote 10,023,045,412 durable PNG bytes.
Peak pending raw bytes were 11,060,184; pending frames, encoders and queued work
were empty at completion.

| Representation | Images | Duration |
| --- | --- | --- |
| Original PNGs/index including final hold | 54,004 | 1,800,141 ms |
| Initial MP4 derivative | 45,006 | 1,800,240 ms |
| Corrected MP4 with terminal repeat | 54,005 | 1,800,142 ms |

The first derivative's duration alone concealed dropped frames: the PNG
demuxer used a 25 FPS time base. A separate terminal-gap case also exposed an
understated endpoint. The correction kept millisecond presentation timestamps,
every image and no B-frame reordering; all encoded packet timestamps matched
the index and met the unchanged 134 ms tolerance.
Original images/indexes and initial movies were not rewritten.

The corrected full movie completed 1× playback without seeking, rate changes
or media-element errors. Recovered source-abort requests remained in the
temporary viewer log, and initial content-length errors stayed retained:
neither was called error-free HTTP delivery.
Prepared arena footage included a deliberate wait, motor interruption,
real death menu and explicit respawn.
This qualified evidence retention for that horizon, not sixteen-hour durability,
autonomous survival, model competence or upstream completeness.
