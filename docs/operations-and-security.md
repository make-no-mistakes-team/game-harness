# Operations and security

GameHarness is an extensible desktop harness for multiple supported games, with Minecraft as its first implemented integration. The [integration guide](integration-spike.md) documents current setup, task controls and scoped gameplay evidence separately from historical cohorts. This document distinguishes supported operation from broader acceptance and release requirements.

The [PRD](prds/gameharness-v1.0-prd.md) owns scope and acceptance. The [architecture](architecture/overview.md) assigns trusted modules; [runtime contracts](runtime-contracts.md) define identifiers, effects and state transitions; [learning and evaluation](learning-and-evaluation.md) defines experimental integrity. [Upstream reuse](upstream-reuse.md) records dependency, authentication and license evidence.

## Current implementation and first adapter

The generic desktop/runtime uses Electron 45.0.0, Bun 1.3.14+, TypeScript and local Docker on Linux x64. The first game adapter adds Java 21/Fabric 1.21.4. Additional supported-game integrations are planned and must declare their own dependencies and evidence; no second adapter is delivered. `bun run build` currently builds that native adapter and Vite renderer; `bun run start` owns the desktop/backend lifecycle. `bun run dev` builds once and opens the same desktop. See the first-integration guide for game-specific prerequisites and sandbox-helper setup.

The trusted Fabric server installer translates `HTTP_PROXY` and `HTTPS_PROXY` into JVM proxy properties, with lowercase aliases and `ALL_PROXY` as a fallback. It supports HTTP proxy URLs without credentials and preserves the JVM's default loopback bypasses. Use `NO_PROXY` for additional destinations, including private or link-local addresses; supported forms are IP addresses, domain suffixes and `*`. Configured proxy credentials, unsupported proxy schemes, and port-specific or CIDR bypass rules are rejected before preparation rather than silently ignored. Without a configured proxy, unused bypass settings do not prevent installation. The child still receives only its restricted environment, not ambient JVM options or provider credentials.

The runtime implements app-owned OMP OAuth/model discovery, durable compact program registration/execution/composition, SQLite evidence, immutable source/cards, local-JS policies and a real Jev broker. The native client/server replace the old Mineflayer/prismarine path without fallback. The reviewed two-trip custom task provides scoped useful-gameplay evidence; historical OAuth/inference/movement and Chrome rendering remain old-spike results. Neither establishes every criterion of the broader [playable gate](implementation-mvp.md#first-complete-playable-gate).

Generated programs/policies run in private Docker containers with no network, an unprivileged user, read-only root, dropped capabilities and finite limits. Source admission checks syntax, body boundaries, imports and forbidden ambient access, with separate 16,384-byte original and canonical UTF-8 caps. Line count, nesting and complexity are descriptive, not rejection limits; comments and coherent helpers are allowed. These [source rules](runtime-contracts.md#current-compact-program-interface) are not sandboxing. Each program execution has its own container; the tree shares action/call/depth/deadline budgets. Only host-known bounded capability waits suspend runnable-computation timing. Ship `sandbox/worker.mjs` and the detached host `sandbox/guardian.mjs`; cleanup stays pending until Docker confirms removal. The pinned Node image must already be present.

Ordinary modules, checkpoint-based recovery and explicit compatible cross-model product imports are required targets, not current body-runtime features. Pure local module calls should share an isolated execution rather than create a process per function. Disclosed mechanics/GUI helpers obey the selected actuator and information profile; prepared development starts are a separately named condition, never ordinary fresh-world evidence. Jev is optional for the autonomous chain, and its actual configured/unavailable/failed state remains visible.

The sandboxed renderer uses authenticated sessions, Host/Origin checks and CSRF-protected mutations. `/v1/video` is a separate outbound binary WebSocket using the same-origin session; no game input or token-bearing query string is allowed. Source/cards/history are inert text. Electron's readiness nonce binds its backend child, not a random service on an occupied port; it closes only owned processes. Runtime credentials, official Launcher bootstrap inputs, private session files and worlds stay outside model inputs and public evidence.

Run stop and world stop differ: run stop fences strategic/program/reaction generations, awaits worker/planner/leaf drain and confirms native input neutralization while retaining a healthy client/video connection. Goal completion and Pause also preserve the session. Explicit world stop, world replacement and app close end owned session/processes; genuinely unconfirmable transport/emitter failure still fails closed. Unknown effects are retained, never replayed. The historical 5.9-second Docker smoke and old-server composite/held-item/death fixtures remain scoped infrastructure history, not proof of the current observation-envelope-3 lifecycle or broader gameplay/release conformance.

Custom natural-language tasks are the default. Optional presets bind exact adapter verifiers; editing their task text returns to Custom. Custom `task_finish` closes the run with a model-reported, unverified completion claim. Program completion and model progress are also unverified; independent review of one episode does not turn those reports into trusted `goal.verified` events.

Native crafting uses visible vanilla 2×2/3×3 screens. Equip and placement's implicit hand preparation use the same exclusive inventory-session custody, with direct hotbar selection when possible. Gestures advance with real world time and remain subject to handler/cursor ownership, effect authority and cleanup fences. Cancellation does not roll back already applied transfers; it revokes pending gestures and may close only its still-owned handler. These disclosed mechanical helpers do not supply gameplay strategy or human-equivalent interaction.

## Early real-integration proof

Use the [Implementation MVP Contract](implementation-mvp.md) to reach a complete playable loop before building every management or recovery feature. This is an intermediate integration gate, not reduced release acceptance. Keep isolation, observation permissions, effect ownership, stop, and stale-output checks in that first loop.

### A real strategic round trip

Connect one strategic model through a legitimate authorized flow. From permitted observations, the model authors and durably starts a bounded program implementing its task flow. Program `game.action` calls receive confirmed effects and feed its own observe/check/recovery logic; meaningful closure/outcomes later reach an autonomous strategic turn. Direct strategic action submission/cancellation is not available. Retain request/program/execution/action/event links. Imports, fabricated responses, operator-driven actions and one-leaf-per-model micromanagement cannot prove primary program execution.

Then show an admitted skill or composite action continuing while strategic inference is in flight, and a model-authored policy responding to a real event in ordinary gameplay. A controlled transport delay is a valid scheduling fault injection, but must be identified separately from measured provider latency. Test the real Jev path early as a separate provider integration rather than assuming the package import exercised it.

The first loop may use one connection. Final acceptance still exercises both authentication categories and achieves the same bounded, verifier-defined task with strategic models from two different providers without editing the core or GameAdapter. Account reconnection and configuration changes do not count as changing the game implementation. Failed tasks remain failed evidence until the interoperability criterion is met.

### Structured observation and navigation

The implemented Minecraft profile is `minecraft_assisted_rgb_360_r8_v1`. Its canonical permissions and finite settings belong in [runtime contracts](runtime-contracts.md). Prove the information boundary without making strict camera-FOV simulation or a complete previously seen voxel map a prerequisite. Information fairness defines permitted facts; the structured state/event interface defines how those facts are delivered.

Nearby unobstructed objects may be observed regardless of camera orientation. Occlusion and range still apply. Keep authorized observations and last-seen memory separate from raw chunks and entity tracking. An occluded entity's remembered position must not update from the raw tracker. A legitimate audible event may produce the profile's coarse sound information, not exact hidden entity or sound-source tracking.

Maintain a second, private geometry-only view for trusted local movement execution. Within the profile's bounded local envelope, the controller may use client-loaded collision/passability/headroom geometry toward an already authorized known target or waypoint. Individual collision voxels need not have appeared in an agent observation; local obstacle avoidance and detours toward that same goal are allowed. This does not authorize hidden resource/material identifiers, entity queries, global loaded-world route planning, or selecting an undiscovered cave, entrance, shortcut, or exploration corridor as a higher-level route.

Check target authority before consulting private geometry. Instrument internal reads, route choices, and actual movement—not only returned path text. The controller must stay within its declared envelope and authorized route intent; otherwise it stops with safe bounded-execution feedback or requests observation/replanning. Do not return private geometry, raw path nodes, reachability grids, hidden-target diagnostics, or resource-dependent errors. Private geometry may affect local steering and timing; this declared advantage is not human-identical perception and must remain fixed across comparisons.

A stock pathfinder is not trusted merely because its output is filtered. Constrain or replace its data path if it cannot use the bounded geometry projection, or use bounded mechanical moves. Neither an unrestricted raw-world planner nor the obsolete all-voxels-previously-seen requirement is the selected design. Record the actual filtering/navigation latency and memory use; do not claim an upstream helper implements the entire profile. See [source evidence and limitations](upstream-reuse.md).

Start implementation with the complete initial preset in the runtime contract, rather than choosing missing limits independently. Materialize its defaults before computing the profile fingerprint. Exercise the [observation performance protocol](learning-and-evaluation.md#observation-pipeline-performance) alongside the information-boundary checks: sampling exhaustion, stale coverage, query/serialization cost and controller delay can undermine fluidity even when LLM latency is low.

Use the following controlled security fixtures in addition to ordinary-world integration:

| Fixture | Required evidence |
|---|---|
| Unobstructed object behind the camera | The in-range object is observable before and after camera rotation. Out-of-range objects remain excluded. Camera orientation alone is not an eligibility gate. |
| Ore behind an opaque wall, then exposed | On a controlled vanilla or Anti-Xray-disabled server, evaluator-only raw diagnostics establish the hidden ore in loaded client state. Agent observations, search results/counts and errors do not disclose it. Remove the occluder through game mechanics and verify authorized discovery. |
| Occluded entity, memory and sound | Exact current hidden position/state is absent. Reveal and hide/move the entity: last-seen memory becomes stale rather than following it. An actual audible event yields only approved coarse sound information, without exact coordinates or a tracking handle. |
| Alternate generated-code/data route | Raw bot/world/block queries, entity collections, renderer buffers, retrieval routes and diagnostic errors cannot bypass the agent-facing API. Filter before exposing result counts, ordering, pagination, or truncation metadata. |
| Local geometry and hidden-route probe | Movement and local detours to the same known target can use private bounded geometry. Swapping a concealed resource for same-geometry stone does not select a target or expose its identity. Unknown-target probes fail before private lookup, and a hidden corridor is not selected as a higher-level exploration route. |
| Optional server obfuscation | Adapter filtering passes with Anti-Xray disabled. If Paper protection is also tested, record its exact configuration and distinguish masked/fake raw block data from genuine observations. It does not replace entity or navigation checks. |

Fixture coordinates, setup instructions, privileged diagnostics and staged situations stay outside agent experience and gameplay comparison inputs. These tests establish information controls, not learned tactics, task success, or performance advantages. Ordinary-world end-to-end runs remain the learning/effectiveness evidence.

### Composite control

Exercise a bounded single-lease action that overlaps movement, camera change, and a permitted interaction or attack on an observed target. Record actual input/effect intervals and show overlap, rather than inferring it from three queued commands. The adapter declares which channels can be combined and the constraints on that combination.

Repeat while a strategic request is pending. Preempt or stop the composite action and confirm neutralization of every included channel before lease transfer. Two independent writers must not be used to manufacture overlap, and a correct ownership check must not serialize every compatible input into separate actions. This is an early integration check, not a handwritten combat strategy.

## Trust and data access

The operator trusts the backend, provider/authentication brokers, GameAdapter observation/effect gates, persistence code and selected upstream dependencies. Generated JavaScript, model output, downloaded documentation, browser content and third-party tool results are untrusted. A local browser UI has operator control authority only through its authenticated session. Authentication is not granted merely because a request arrives on loopback.

| Data or capability | Allowed holder | Forbidden exposure |
|---|---|---|
| Raw game engine/protocol state and privileged queries | Trusted adapter only; narrowly scoped privileged evaluator where necessary for result verification. | Strategic context, skills, policies, generated workers, ordinary tools and their errors. |
| Profile-authorized state and legitimate remembered observations | Adapter filter, backend, authorized planner/workers and environment-scoped memory. | Promotion of unobserved content to current facts; cross-environment transfer of local maps or handles. |
| Profile-permitted private terrain geometry | Trusted low-level controller, through a bounded geometry-only projection for authorized local movement. | Agent context, generated code, remembered-object index, raw path/reachability output, resource targeting, or undiscovered route selection. |
| Hidden targets/semantic world facts, hidden environment identifiers, save files and backups | Operator/game storage; isolated result-verification path only when necessary. | Planner context, resource/structure/entity navigation queries, reusable agent memory, public diagnostics, renderer-to-agent shortcuts or retrieval results. The private geometry allowance does not include these facts. Authorized image metadata may identify host selection scope; its unsynchronized run/world/session/epoch/life/generation fields do not establish capture-time gameplay identity. |
| API keys, OAuth access/refresh tokens and provider sessions | Trusted provider/authentication broker and protected credential store. | Worker environment/files, model prompts, events, URLs, frontend state, generated artifact metadata or logs. |
| Game account credentials/session | Trusted operator-owned game login path/adapter as required. | Generated code, project distribution, browser activity feed or model context. |
| SQLite database, artifact store and host files | Trusted backend with least necessary access. Workers may receive bounded copies of their own authorized serializable state. | Worker mounts, direct SQL tools, arbitrary paths or host filesystem access. |
| Live-view backing data | Trusted adapter/renderer transport and authorized human browser; the planner receives only the bounded typed PNG selected by [`Runtime.modelObservation()`](runtime-contracts.md#delivered-actor-images-and-recorded-episodes). | Agent HTTP access, arbitrary backing-state/image/viewer-route retrieval, raw buffers/protocol objects and hidden-state export through viewer errors. The actor path grants none of those permissions. |
| Public documentation/web content | Trusted retrieval broker returns bounded attributed text. | Ambient worker networking or access to local/private resources through URL redirects. |

Privileged verification must use a separate output path. Its hidden-state evidence may establish an objective result for the evaluator, but cannot flow back into planning, policy inputs, skill memory, generated code logs or experience libraries. Filtered agent telemetry and privileged evaluator records need distinct access rules even on a single-user host.

## Provider connections and credentials

Support both API-key connections and legitimate provider-supported subscription/OAuth connections. This is not a promise that every consumer subscription grants arbitrary model access. The provider adapter determines the supported connection mechanism and entitlement. Reuse only authentication interfaces whose exports and storage behavior have been verified, as recorded in [upstream reuse](upstream-reuse.md).

The operator initiates connection from the trusted local UI. For an API key, the backend receives it through an authenticated same-origin flow, stores it using the chosen protected host credential mechanism, and returns only an opaque connection reference and redacted status. It must never echo the value to the UI or event ledger. Provider-account secrets must not be submitted to generated tools.

For OAuth/subscription access, the trusted provider adapter owns authorization initiation, callback/device exchange, state validation, PKCE where the provider flow requires it, token storage and refresh. Any callback listener has a narrow purpose, expected redirect binding and finite lifetime; it does not expose game-control routes. Device codes and authorization URLs are displayed only in the trusted operator flow and are not recorded in shared diagnostics. Unsupported or failed entitlement is an explicit connection error, not a reason to scrape browser sessions or bypass a provider's terms.

The current Codex browser flow presents the validated provider HTTPS authorization URL at `auth.openai.com/oauth/authorize`, not the SDK's optional loopback `/launch` shortcut. Validation rejects credentials, fragments, unexpected hosts, ports and paths. Renderer and desktop external-link restrictions remain unchanged. Browser authorization returns through the state-checked local callback on port 1455; device-code authorization at the validated `/codex/device` address is the supported alternative when that port is occupied or callback login is unsuitable. Available flows and retained authorization/discovery success do not establish independent live testing of both flows.

At run start the backend resolves an opaque connection to the selected model and role. Workers can request a permitted provider operation through a broker; they never receive the secret or a general-purpose HTTP client. The broker checks capability, role, model, input projection, deadline, concurrency, finite attempts and output schema. It records logical decisions separately from actual attempts, usage where reported and known/unknown cost. Reliability deadlines, concurrency and attempt bounds are distinct from monetary accounting; they do not imply a dollar-based stop gate.

Revocation or expired refresh credentials marks the connection unavailable, rejects new requests and fences late callbacks. The UI asks the operator to reconnect through the trusted flow. Already admitted bounded gameplay can finish or be cancelled according to its normal contract; no extra strategy or substitute backend is silently selected. The agent can choose validated local-code policies when available. Jev failure remains a Jev failure in evidence, even if later code-only operation proceeds.

Local tool schemas and the SDK's actual request are separate evidence boundaries. For optional/discriminated inputs, explicitly control provider strictness rather than assuming omission preserves local schema semantics. The [Responses strict-mode contract](https://developers.openai.com/api/docs/guides/function-calling#strict-mode) allows normalization when strictness is omitted; explicit `strict:false` selects best-effort arguments. It does not relax host parsing, role authority, source limits, admission or cancellation fences. Exercise the real SDK request construction with a zero-network capture before consuming another live allowance; absent remote grammar remains unknown, not proof that a model or provider caused a failure.

## Browser and local transport controls

Bind backend controls, adapter control transport and viewer to loopback by default. The reference deployment has a native host backend/adapter and private isolated worker processes or containers; it does not require containerizing the game or the entire application. A development frontend port is a distinct origin and needs an explicit temporary allowlist; production should serve the UI from its configured local origin where practical.

The backend must validate expected `Host` and `Origin` values to resist hostile pages and DNS rebinding, issue a local session through a trusted bootstrap path, and require authenticated command authorization. Use explicit allowed origins, never reflected origins or a wildcard. Cookie-based sessions require the appropriate SameSite/HttpOnly settings and anti-CSRF validation for mutations; a bearer-based local mechanism must protect its token from URLs, history and logs. Read endpoints and SSE also require authorization. No control mutation is allowed through a GET request.

UI text, retrieved material, model explanations and source snippets are untrusted display data. Render as text or sanitize through a deliberately restricted renderer; do not execute embedded HTML, scripts or event handlers. Choose a content security policy and origin separation that keep generated content from executing with operator control authority. A malicious activity-feed entry must not become a start/stop/provider command.

Authorized generated source code may be displayed as escaped, non-executable text. Viewing it grants no permission to execute a program, install or activate a policy, or retrieve another run's data or secrets. Source and evidence reads retain their existing authorization and information-filtering rules.

Apply equivalent authorization/origin checks to the viewer's actual transport, including HTTP/WebSocket where used. A human may view rendered game state, but the agent capability broker cannot request those routes. Internal adapter control messages use private authenticated transport, not a browser-reachable raw-engine interface. Port secrecy and browser CORS alone are not authorization. Browser disconnects show a stale-view warning; they do not silently stop or pause an otherwise healthy run.

## Generated-code isolation

JavaScript evaluation in a regular process, Bun/Node worker, `eval`, or a VM context is not a security sandbox. The release must run generated code inside an enforced OS isolation profile: a restricted child process with actual OS security controls, or a private container with equivalent controls. Unrestricted upstream coding-agent execution is not reusable as this sandbox.

The isolation profile must enforce:

- A dedicated unprivileged identity; no privilege escalation, host namespaces, host sockets, container-management socket or other route to privileged processes.
- No network access, including loopback, private subnets, link-local/cloud metadata, DNS tunneling and viewer/provider endpoints. Approved provider/docs/web requests cross trusted brokers.
- A read-only minimal runtime with no mounted source checkout, home directory, credentials, database, world/save directory, host `/proc` view, or unrelated process environment. Only the immutable selected artifact and bounded private scratch/state are provided.
- A narrow framed IPC interface that accepts only serialized, schema-checked capabilities. No object handles, callbacks, raw adapter references, arbitrary imports, host commands or arbitrary path reads.
- Finite wall-time and CPU/memory/process/output/IPC limits. Nontermination or flooding terminates the worker, revokes its execution generation, records evidence and quarantines the offending policy version where applicable.
- Cleanup of descendants and ephemeral state on termination. Lease safety is maintained by the trusted executor even if a worker is killed mid-request.

Isolation and observation filtering solve different problems. A perfectly isolated worker could still cheat if a broker returns forbidden game state. Every action, tool, error and retrieval result must pass the selected adapter profile's data policy. No transient debugging mode may expose secrets or hidden state to an agent run whose evidence is presented as ordinary-player performance.

### Brokered documentation and web

The broker accepts only supported public documentation/web retrieval, bounds response size and elapsed time, records URL/source/time and returns text marked as untrusted external content. It rejects local files, non-public addresses, loopback, private/link-local addresses, credential-bearing URLs and privileged viewer/control routes. Resolve and validate the destination at connection time and after every redirect; apply equivalent restrictions to proxy behavior and alternative address forms. Workers do not supply arbitrary headers, cookies or authentication material.

Queries must not leak account secrets, hidden environment identifiers/state or private run data. Public game documentation, API references and general pretrained knowledge are allowed; looking up a hidden environment or uploading its save for privileged analysis is not. Retrieved text cannot grant new capabilities or override system/task instructions. A retrieved instruction to read a credential file is content to ignore, not an authorized tool call.

## Operating lifecycle

Startup and run controls below describe the supported lifecycle. Broader recovery/checkpoint procedures are identified as release requirements where the current runtime does not implement them. Completion requires observed status and durable evidence, not the mere presence of lifecycle code.

### Startup

1. Check the supported host runtime/dependency versions, isolation availability, writable trusted persistence locations, private transport configuration and required local resources. Fail clearly before gameplay if a mandatory security control is unavailable; never substitute unsandboxed execution.
2. Load protected connection references and report redacted provider capability/availability. Actual account secrets stay in their trusted flow. An unavailable optional fast backend is visible; Jev support itself remains a delivery requirement.
3. Open SQLite with foreign keys, WAL and the selected durability settings; check migration/version compatibility and immutable artifact hashes. A single trusted backend owns writes. Refuse competing owners rather than creating two schedulers for one avatar.
4. Start/connect the selected game and trusted adapter under operator-owned configuration and terms. Check descriptor, game/adapter/profile/schema identity and actual capability/support levels. Keep effect admission closed until a new authorized session/epoch and authoritative permitted observation exist. Verify profile rules without exposing privileged configuration to the planner.
5. Establish the adapter's declared live view and authenticated UI, select the task/model/connection/world and compatible immutable library snapshot, and create the full run manifest defined in [runtime contracts](runtime-contracts.md#run-manifests-and-compatibility). A held-out environment must not inherit its local map from practice.
6. Complete host preflight and begin ordinary bounded scheduling only after fresh observation and admission checks succeed. Keep capabilities equal for cold and warm runs; record actual preparation, requests and first effects. No model ceremony is required to reconfirm host-known readiness. Starting without a selected reaction is valid.

The release must provide meaningful readiness errors: unsupported game/profile version, adapter protocol failure, port/origin/session failure, missing isolation, persistence incompatibility and provider entitlement failure are different conditions. Do not call readiness failure a gameplay defeat.

### Pause, resume, stop

Pause closes effect admission, revokes pending generated evaluations and strategic callbacks, cancels active skill/action work, and waits for acknowledged neutralization or the adapter's documented safety fence. The UI stays in `pausing` until safety is established. Agent pause does not imply world pause: the selected adapter declares whether the game keeps running, disconnects, or supports an explicitly requested world-pause operation. Display actual behavior and consequences. A world pause must be attributed and must never conceal inference latency or occur automatically for ordinary model waits. No developer strategy is inserted during pause.

Unknown past effects and live emitters are separate facts. `GameBridge.neutralize()` must acknowledge the real native input barrier, independently of disconnect, before healthy run closure. Missing control rejects rather than fabricating acknowledgement. Unknown action/root outcomes remain unknown after safe drain. The earlier 375 ms death-teardown fixture required client exit and retained a death error; that cohort is historical and superseded, not the current ordinary-death policy.

Normal death changes player life, not game-session or run ownership. Revoke old-life commands/targets, drain affected roots and reactions, reject late JS/Jev/lookahead results, preserve last authorized context and wake the strategist once. Keep the healthy client/video connected and `game.error:null`, showing the actual vanilla DeathScreen. No saved-dead startup or death handler requests respawn. Only explicit model-selected `game.respawn()` or `{kind:"respawn"}` through the exclusive arbiter can request vanilla respawn; timeout remains uncertain without replay. Confirmed alive readiness advances life ID while preserving session UUID/epoch. Other old-life work stays fenced.

Record operator pause intervals separately from LLM waits, meaningful game waits and infrastructure downtime. Explicit Resume requires an authoritative fresh observation, new execution generations and confirmed prior-owner drain. Unconfirmed emitter closure or native neutralization requires a fresh connection epoch before Resume; fresh observation alone does not repair that failure. A replaced native session/profile requires a new run. Do not replay pre-pause queued actions. Pause during bootstrap ends that bootstrap early; resume enters ordinary gameplay without a fresh bootstrap allowance, while normal policy-authoring tools remain available.

Stop has highest priority. It closes admission, revokes generated work/provider callbacks, cancels actions, confirms neutral controls and worker/planner/action drain, then durably closes the run. A healthy playing session and authentic video remain connected. Stop world, world replacement and application close explicitly own session shutdown. If contact is lost and effect safety cannot be confirmed, fail closed and preserve stop intent during recovery. `stopped` means safe run closure, not merely a clicked button.

The operator view separates acting, program execution, model thinking, waiting, blocked work and recovery from paused/closing states. Progress records retain event sequence, time and execution identity with `model_program`/`unverified` provenance. **Model request failed · paused** reports a failed request, not a diagnosed provider-wide outage. Inspect its cause and connection state; refresh model discovery where appropriate before explicit Resume. Reauthorization requires Stop first. **Stopping** remains pending until cleanup is confirmed; **Retry Stop** retries cleanup after a recorded error, not gameplay. A stopped run cannot Resume.

The emergency procedure must include a trusted path independent of generated workers and ordinary inference: fence adapter effect admission, terminate the emitting worker/adapter process if necessary, and establish session disconnect or neutralized controls according to the declared game protocol. Closing the browser is not this procedure. A graceful shutdown first requests normal stop, then closes trusted storage and owned processes. An abrupt process kill is recorded as a failure/recovery event; it is not evidence of cancellation.

### Recovery without erasing the attempt

Unknown past effects on a healthy alive connection do not automatically require a reconnect or human Resume. Fence affected roots/planner/policies/leases, retain unknown outcomes, await real native neutralization plus complete worker and old-history-owner closure, and obtain fresh same-session/life authorized state. Confirmed reconciliation permits exactly one new strategic generation/`uncertainty` wake; the model chooses new work and no old effect is replayed. Unconfirmed barrier/drain/readiness instead keeps admission closed in paused/fail-closed handling until explicit Resume can establish safety. Failed emitter/native drain additionally requires a fresh epoch; a history-only failure grants neither input authority nor automatic reconciliation. Death routes to the existing life-recovery path; real transport failure still requires owned-emitter fencing/teardown. The reconnect procedure below applies when the connection actually needs replacement.

The current application restart retains inspectable objective/events, immutable source and unresolved outcomes, reconciles unfinished records and closes an interrupted run without automatic replay. The operator creates a new run for subsequent gameplay; the interrupted history remains intact. This is not automatic whole-process continuation, restoration of a JavaScript stack or restoration of game state. Live Pause/Resume and fresh-state reconciliation within a surviving process have a different scope.

The following same-run infrastructure-recovery procedure is a broader release requirement, not a description of automatic restart today. It must preserve `run_id`, advance `epoch` where session authority changes, record outage/intervention intervals and keep unknown outcomes visible. An explicitly separate run must never conceal the failed segment of an experiment.

1. Close effect admission. Preserve pause/stop intent. Revoke old request, evaluation and lease generations; terminate or demonstrably fence old workers and adapter connections. A timed-out promise alone is not a fence.
2. Reopen compatible durable storage and reconcile the last committed run/event/action records. Detect incomplete checkpoint/artifact writes. Do not infer successful effects from an action's recorded intention.
3. Reconnect the trusted adapter, verify manifest compatibility, advance/persist the epoch before admitting effects, and obtain authoritative profile-filtered observations. Recreate deadlines from new local clocks; old-process monotonic values cannot establish freshness.
4. Reconcile actions. No-start admitted jobs can fail as invalidated. In-flight effects without conclusive completion evidence become `unknown`. Never blindly repeat an effect because its result was lost. Current observed domain state can inform a new decision without pretending to prove the old history.
5. Load hash-verified compatible artifact versions and serializable state. Reconcile world-local memory with current observations and any rollback branch; retain uncertain facts as uncertain or invalidate them. Summaries do not override source events or current game state.
6. Emit a recovery report with outage cause, old/new epoch, unknown effects, memory/artifact decisions, interventions and authoritative state changes. Return to `paused` if pause intent was present, finish stop if stop intent was present, otherwise resume only after safety and freshness gates pass. If safe fencing or compatible recovery cannot be established, mark `failed` with evidence.

A provider-only failure does not itself require a new game session or epoch. Current strategic request failure records its cause and pauses control; after readiness is restored, explicit Resume uses fresh observations and rejects stale work. This source behavior and selected offline interruption proofs do not establish a live provider-outage recovery result. Silent backend substitution is never evidence that the failed request succeeded.

## Checkpoints, reset and restoration support

This section specifies required checkpoint/restoration semantics. The current compact-program runtime retains durable evidence and safely closes interrupted work; it does not deliver general game/runtime checkpoint restoration, JS-stack continuation or ordinary-module recovery. Existing worlds and source bytes are not evidence that those capabilities are available.

The backend owns local SQLite records for runs, events, action ledger and artifact metadata. Immutable source/configuration files use content hashes. Store source/event evidence independently of lossy conversation summaries. A runtime checkpoint identifies its game/adapter/profile/schema manifest, run/world/epoch/branch, durable event cursor, action-ledger state, selected artifact hashes and state-schema versions, and serializable memory references. It does not by itself capture game state. An incomplete checkpoint is not advertised as recoverable.

Commit an artifact's durable immutable bytes before committing registry metadata that references them. Commit related run/action state and events in one database transaction. Conversation compaction can produce an additional derived artifact with provenance; it cannot replace the action ledger, source programs or world state. Avoid copying a live WAL database as if its main file alone were a backup; use an appropriate SQLite consistent-backup procedure and verify it as part of future release work.

The trusted history reader opens only an existing writer-prepared database in
SQLite readonly mode. It does not construct the writable Store, migrate or repair
schema, create directories, change permissions or select arbitrary paths from a
query. Startup checks schema and required index readiness. Source reads verify
the stored hash against raw bytes before UTF-8 decoding; absent historical
authority remains absent. Its fixed executable/module and storage paths are
selected by the parent, with no inherited credential, proxy or preload settings.
The query protocol exposes no SQL, mutation, game-input or provider endpoint.
This is a trusted backend read service, not the Docker sandbox for generated code.

The writer migrates run databases to schema 7 before readonly access. Lazy source
MVCC preserves raw values as of a fixed source sequence, including late updates
and deletions. Source-key bootstrap and reads use pages of at most 128 rows.
Readonly previews produce bounded derived patches; only the writer can validate
and atomically commit them with opportunity captures and checkpoint progress.
Reopen resumes committed work, while readers retain the last complete published
generation. The checkpoint is derived bookkeeping, not a game/runtime restoration
point or authority to replay an effect. Opening a readonly connection never
initializes, advances or repairs it.

Each preview allows at most 64 patches, 16 candidate captures and 128 work
iterations. Complete request and response frames, including envelope and newline,
remain bounded to 8 KiB and 64 KiB. Before committing a continuation, the host
checks that the next complete request fits; an otherwise valid reply cannot
strand durable work behind an oversized request. Preparation retains one active
caller and eight FIFO waiters per run, with each caller's original deadline and
cancellation. Failure grants no automatic retry or deadline renewal.

Each compound query releases its deferred read transaction before serialization
or idle waiting, so an idle reader does not pin the WAL. Abort, timeout and
shutdown retain process ownership until actual exit and pipe drain; a replacement
can start only for a distinct request after that barrier. Query failure does not
authorize a retry, a fabricated observation or an empty successful result.

Pause and Stop fence native input before awaiting history preparation/query
drain, so metadata work cannot delay revocation. Queued old-turn work is cancelled.
Effect-free history may later resume under separate ownership, including after
Stop; it never resumes gameplay or provider authority. Application close
permanently closes history admission and joins all producers/readers before Store
closure. Failed drain remains unconfirmed rather than being cleared by a timeout.

Published pages disclose their generation, source boundary and pending work.
Full-record byte omissions retain recovery references through the named actor
metric/evidence views and the operator's generation-pinned execution routes
defined in [runtime contracts](runtime-contracts.md#current-compact-program-interface).
These remain authorized evidence reads, never SQL, arbitrary paths or effect
capabilities. A missing first publication is pending; a missing generation that
was already published is corruption and conflicts rather than becoming an empty
or current-looking result.

Game-state checkpoint, reset, restore and world pause are independent adapter capabilities, each declaring `unsupported`, `operator_assisted` or `adapter_managed` as defined in [runtime contracts](runtime-contracts.md#gameadapter-descriptor-and-interface). The UI and recovery procedure use actual negotiated support. A runtime checkpoint cannot upgrade an unsupported game save/restore mechanism. If a game requires an operator-controlled restart, that intervention and its confirmation remain pending until observed; no synthetic success or fake fallback is recorded.

A database transaction cannot atomically commit external game effects. A game-state checkpoint declaration must state consistency boundaries, required neutralization, whether the environment continues evolving, and what durable acknowledgement/evidence exists. Record separate game/runtime checkpoint identifiers and event bounds; do not imply an atomic snapshot where the adapter cannot provide one.

Reset and restore first close effect admission and fence old work. Restoring an older environment checkpoint is an explicit rollback branch: retain the original `world_id`, allocate `rollback_branch_id`, record parent checkpoint identifiers and advance epoch. Agent world-local memory records branch provenance. Invalidate or mark uncertain facts and domain assumptions acquired after the restored point; summaries do not preserve facts contradicted by restored state. Compatible abstract experience may remain, but evaluation labels the intervention and any advantage. A reset that creates a replacement environment gets a new `world_id`; invalidate prior environment-local memory. Authoritative reobservation and compatibility checks precede resumption.

Policy rollback is different: selecting a previous immutable policy version changes future decisions through the runtime's atomic switch; it does not restore game state or elapsed time. The evaluation recorder's offline video derivative is review playback, not an in-app replay browser or deterministic environment rewind.

## First integration: Minecraft server and saves

The native reference integration pins Minecraft Java 1.21.4/Fabric under Java 21, Normal Survival, one avatar and ordinary spawn/inventory/death rules without cheats/operator privileges. Operators must obtain game access legitimately and accept the server EULA. The official Launcher's local account is used only through the trusted private client bootstrap, never copied into repo/logs or agent context. Verify actual versions/rules/privileges before collecting gameplay proof.

The trusted native client owns raw world/chunk/entity state and filters before queries, counts or serialization. The current `minecraft_assisted_rgb_360_r8_v1` profile allows bounded unobstructed observations without camera-FOV gating, own state/UI, permitted coordinates, public recipes/docs, coarse real sounds and world-local memory. Hidden resource/structure targets, exact concealed entity state, seeds, saves and raw objects remain unavailable through tools, programs, errors, logs or retrieval. Private controller geometry cannot become another observation interface.

Production controller feedback acquires permitted nearby world geometry at most twice per second within one life/space/screen scope. Faster body, camera and sound feedback does not trigger another geometry scan or renew the retained geometry's acquisition time. Explicit Runtime observations still acquire fresh permitted state and seed that shared cache; the two-per-second limit applies to controller sampling, not those requested reads. Assisted native effects retain custody of their geometry instead of receiving background refreshes, and scope changes invalidate the cache.

The managed server verifies private session proof before ordinary login/duplicate-player handling; same-name connections must not displace the owned player. Host-admin adversary protection is outside scope. Control authenticates session/world/epoch independently of bounded latest-frame video. Ordinary physical gameplay/menu callbacks and polling are suppressed in the owned client. Human video access grants no agent frame/buffer capability. Version, account/admission, control and video failures need distinct diagnostics.

On Linux, the official Launcher's selected-account bearer may live in the unlocked GNOME Secret Service rather than its intentionally blank JSON token field. The one-shot `/usr/bin/python3` / `python3-dbus` helper reads the active account's exact local token key through a private pipe; the trusted launcher verifies the matching official profile. It never substitutes another account, unlocks a keyring or imports unrelated app credentials. No bearer reaches argv, tracked files, logs, workers or model context. This narrow OS binding does not move gameplay or agent orchestration into Python.

Native own-inventory verification uses authenticated receipts bound to the connection's session/world/epoch and the request nonce/motor generation, ordered after vanilla packets. Limit receipts to bounded own item counts/slot names; exclude NBT, other world/player data, admin access and action authority. They remain internal, not model capabilities. Local click prediction and packet acknowledgement alone cannot prove inventory gain, and receipt implementation alone is not a passed gameplay task.

The default pause, Stop run and goal completion leave a healthy session connected and the world ticking; warn that survival is not guaranteed. Cancellation stops motor/navigation work, releases held inputs and obtains real neutralization acknowledgement, or enters the declared fail-closed bridge fence/recovery path. Ordinary death retains the session and awaits an explicit model respawn decision. Stop world ends the owned session and server. Lost craft/place/consume/respawn results must never be blindly replayed.

Current observation envelope 3 carries session/life/native-boot, space/screen and compatibility identity. Historical schema-2/r2 records retain their original lineage, including nulls where evidence is absent; never invent IDs for them. The current profile remains camera-independent structured line of sight. Optional current ItemEntity `item_name` exposes only the represented stack's registry kind after the existing range/occlusion/currentness gates, never dropped-stack counts, NBT or hidden item identity. Operator motor profiles persist through `/v1/config` and apply live; free look and gaze selection do not widen observation permissions or authorize navigation toward a hidden goal.

Minecraft saves are a separate consistency domain. Where server save/flush support is available, a coordinated backup stops admitting actions, neutralizes the avatar, obtains supported save/flush acknowledgement, then captures the world backup and agent checkpoint with their respective identifiers and acknowledgement/event bounds. The world may keep ticking between boundaries; record the interval instead of claiming one atomic snapshot. A stricter backup may require an explicitly recorded operator server shutdown after safe agent stop. Neither is an invisible gameplay pause.

The adapter must declare whether each environment's backup/reset/restore procedure is operator-assisted, adapter-managed or unsupported; possessing a directory of files is not proof of a valid restorable backup. Restoration follows the generic rollback-branch procedure and invalidates post-restore location, inventory and UI assumptions. Policy rollback cannot restore inventory, health or terrain. A trusted Minecraft task verifier may establish subgoals or actual Ender Dragon completion, but its privileged evidence remains outside agent context.

### Optional Paper Anti-Xray

Paper Anti-Xray is optional defense in depth, not a prerequisite or a replacement for GameHarness filtering. The required adapter checks must pass with server obfuscation disabled. Protection against hidden blocks does not establish protection against hidden entities, private navigation data, or other indirect information channels. The [upstream evidence](upstream-reuse.md) records documented defaults and limitations; no Paper deployment has been exercised here.

If used, retain server flavor and exact build/game version, effective per-world/dimension Anti-Xray enabled status and configuration, and a configuration snapshot/hash in the experiment manifest. Record applicable engine mode, block lists, height and update settings for that actual build. Do not assume current Paper documentation exactly describes a pinned older build, and do not change obfuscation or observation/navigation permissions between matched runs. Seeds and privileged raw diagnostics remain evaluator-only. Masked or fabricated client blocks must not be reported as genuinely discovered resources.

## Diagnostics and evidence retention

The operator needs actionable causes without a second channel for secrets or hidden state. Use structured safe error categories and correlation IDs. The trusted runtime records sanitized version/configuration manifests, admission decisions, provider attempt/latency/usage metadata, cancellation acknowledgements, rejected stale responses, quarantines, lifecycle transitions and recovery reports. Preserve actual objective evidence and known partial effects. See [runtime feedback](runtime-contracts.md#feedback-and-evidence) for record semantics.

Redact before persistence and display, not only when exporting. Exclude keys/tokens/device codes, authorization headers, credential-bearing URLs, account session payloads, hidden environment identifiers/state, raw protocol dumps, save-file contents, private filesystem paths and arbitrary dumps of worker/provider objects. Use allowlisted diagnostic fields; untrusted error strings and model output require the same sanitization. Do not log every environment variable or HTTP body to investigate an authentication failure. Renderer/game visuals can reveal legitimate visible gameplay; storage and sharing remain operator decisions.

Keep privileged evaluator evidence apart from agent-visible logs. Source programs and authorized events are evidence, while lossily compacted summaries are derived memory. The UI must accurately label incomplete observations, stale views, unavailable metrics, unknown effects, rejected responses and absent cost data. Unknown pricing is not zero cost.

Record interventions by kind: infrastructure restart/reconnect, manual pause, task change, world restore, account reconnection, and tactical human coaching. Coaching is separately labeled from ordinary infrastructure maintenance. Preserve wall-time, active gameplay and downtime as distinct intervals. A recovered run remains reportable with its full history; do not delete its failed segment or reset its metric origin. Retention/deletion choices must be explicit to the operator and must not silently remove evidence supporting a reported comparison.

The evaluation recorder retains delivered native frames as private PNGs, an index and a completion manifest independently of the latest-frame desktop view. Its [finite recording bounds](integration-spike.md#episode-recording-and-retained-evidence) and persistence/encoding failures are explicit; incomplete recording requests run Stop rather than silently dropping evidence. Finalization drains queued work and closes the index. Optional offline rendering preserves original evidence on failure and awaits the owned renderer's actual exit on abort/deadline. A complete manifest means delivered-frame retention, not every native render, synchronized state/capture, audio, a trusted goal result or an in-app replay feature. Treat frames and review video as private until deliberately reviewed for sharing.

### Private evaluation storage

[`evaluationPaths`](../src/evaluation/paths.ts) separates compact reports, private runtime material and durable governance state. Reports default to `reports/evaluation` in the checkout. Runtime material defaults to the XDG cache root and governance to the XDG state root, each scoped by the checkout's canonical identity. `GAMEHARNESS_EVALUATION_REPORTS_ROOT`, `GAMEHARNESS_EVALUATION_RUNTIME_ROOT` and `GAMEHARNESS_EVALUATION_GOVERNANCE_ROOT` override those locations; explicit function options take precedence. The three roots must be separate and non-nested.

New worlds, game JARs/JRE/libraries, client profiles, session/credential material and full private evidence belong in runtime storage, not compact reports. The [private journal and episode recorder](learning-and-evaluation.md#environments-and-tasks) retain separately bounded evidence; compact reports and ordinary capped Store traces do not contain everything those paths retain. The attempt ledger belongs in governance storage so creating a run directory cannot reset it. This evaluation layout does not change Electron's application storage or `GAMEHARNESS_DATA_DIR`. Existing historical evidence and worlds remain unchanged; relocating new output does not sanitize or migrate old bytes.

Diagnostics and immutable study declarations share the private governance database without sharing allowances or inventing hypothesis aliases. Study registration freezes permission, source/reference hashes, actual execution identities, scheduled slots and finite allocations. Reserve a live slot before opening authorization or preparing native resources; missing/mismatched/unsupported declarations fail first. Admission-only mode rejects external-resource flags and records `not_run`/`not_called` with no verified goal.

Minecraft development acceptance retains an evaluator observation before gameplay for its independent baseline and another after run closure for final verification and private evidence. During gameplay it does not poll observations to refresh actor geometry or stop the run on an evaluator verdict. Runtime owns normal preflight, strategic-context and admitted program/reaction observation reads; its registered verifier can complete a built-in criterion from those production observations or confirmed effects. A custom task's completion claim remains unverified. Registered studies and standard scenario acceptance retain their declared evaluator polling; this development policy does not change frozen protocols.

The finite acceptance launcher starts its non-study clock at task submission, before fixture creation or authorization. One original deadline covers preparation, discovery, native/runtime startup, gameplay, required final observations and verification, evidence persistence, and actual cleanup. Cleanup reserves the declared `caps.cleanupMs` from the total and keeps any stricter Stop or signal limit. Early development preparation has at most 300,000 ms. One finite example envelope uses `caps.totalMs: 625000`, `caps.runMs: 240000` and `caps.cleanupMs: 25000`, reserving 60,000 ms for required verification, evidence and rendering after maximum preparation and gameplay; these are explicit example caps, not all development defaults. The acceptance CLI supports `--total-ms` and `--run-ms`; cleanup is an API cap, not a `--cleanup-ms` flag.

Development evidence profiles must cover the complete total window, including recording prelude and drain. A 625,000 ms declaration needs `recording.maxDurationMs` of at least 625,000 and `recording.maxFrames` of at least 18,751 at nominal 30 Hz with a final-frame margin. Supply a complete project-local JSON profile through the existing `evidenceProfile` option or `--evidence-profile`; the default 12,000-frame profile cannot cover that envelope.

Expiry fences further resource and model admission. A timed-out create, preparation or close remains owned until its original operation settles; the launcher does not abandon it or start a replacement. If actual drain or final report persistence exceeds the original deadline, cleanup stays unconfirmed even after the owners eventually join. Native fixture reports separately retain actual closure in `cleanup` and any missed cleanup bound in `cleanup_deadline_reached`; late closure cannot produce `pass: true`. A signal during pending creation tightens shutdown even after work expiry, preserves the first interruption reason, and keeps the startup finalizer joined through main cleanup. A blocked owner can therefore delay return beyond the declared budget, but cannot turn that late return into a successful bounded sample. Registered studies keep their separately frozen registration/reservation deadlines and interrupted failure histories.

Each currently admitted cold study slot uses a fresh fixture Store and fresh working programs, with global experience retrieval and promotion unavailable. Keep manifests, hidden initialization, verifier truth and sibling artifacts outside actor tools, prompts, logs and retrieval. Optional replication is a preregistered whole block with an immutable activation/decline record. Retain inactive slots separately from started outcomes; safety, authority/leakage and invalidating platform failures close further admission.

An unresolved reservation keeps its slot and conservative allocation across restart. Do not infer resource release from a dead PID or terminal usage event. Actual stream/Agent/native/worker drain is separately acknowledged; later confirmation cannot change an interrupted outcome or refund unknown consumption as zero. The local governance owner reuses its fixed prepared statements and finalizes all of them before synchronous database close. Current restore/prepared-save, inherited-library, frozen/alternative-controller and Jev study modes remain unavailable before external setup.

Compact reports retain provenance and explicit missing/relocated evidence. They are not automatically public: preserve full private originals and review any selected material before publication. Keep worlds, auth/session stores, raw logs/frames, launcher profiles and private plans/transcripts out of public source and documentation. A checkout exclusion alone does not sanitize copied files.
