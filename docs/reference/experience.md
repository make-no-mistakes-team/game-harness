# Experience, working programs and reuse

Reusable source is not remembered world state or a running worker. Generic GameHarness distinguishes same-session working candidates, evidence-qualified snapshots and broader release knowledge/startup-bundle requirements.

## Delivered working definitions and snapshots

Run creation selects continue or fresh working programs. Continue imports exact compatible validated closure for the same session/model; fresh omits it. Keep one coherent latest selection with dependencies. A new same-name definition replaces selection coherently without editing original source or mixing closures.

Working candidates carry no old invocation args, observations, private state or stacks and are not qualified cross-session experience.

Promoted snapshots retain exact source/cards/dependencies, authoring model/profile and run/world provenance plus attributable useful gameplay. Hydration creates fresh state without old args/observations/stacks. Portable intent cannot contain world data; world-local reuse requires same world. Hash/declaration checks are not proof of semantic portability/generalization.

Current library is model-scoped, not implicit cross-model global catalogue. Explicit compatible cross-model product import is a target that must preserve authoring provider/model and recheck applicability/security. Sealed studies retain private selected snapshots and refuse unsupported inherited conditions.

## Evidence gate

Native inventory qualification requires confirmed authoritative own before/after receipt and eligible predicate within the **closed root's bounded interval**. Exact craft/dig target plus trusted task verification may attribute delayed pickup only inside that interval; later gains cannot retroactively qualify it.

Trusted-goal cancellation may close an eligible root without pretending self-completion. Local prediction, model assertion and aggregate possession alone are insufficient. Promotion selector reads typed adapter evidence, checks scope/interval/baseline gain and follows life adoption only when linked to that root's own successful respawn and matching new-life observation.

Goal evidence validates adapter/verifier and resolves typed referenced receipts/observations. Direct removal/final-product, inventory collector, prerequisite production acquisition witness and block-removal contributor are different roles. Combined acquisition→production→possession must be same-life ordered. All retain unknown causal item origin; possession does not prove exact item provenance. Historical v1 goal payload decoding stays read-only.

## Selective experience requirements

Broader release search/get/save-knowledge/propose-promotion/performance-history are scoped concepts, not extra aliases. Current tools/help own callable operations.

Server derives pinned model/game/adapter/profile/capabilities/snapshot/private branch from run. Caller filters only narrow scope; shared source bytes grant no sibling evidence. Search returns compatible bounded metadata/card/performance summaries, not every source. Exact get returns selected immutable content/hash/provenance, never latest or close-enough substitution.

Unknown/empty history means unmeasured, not success. Incompatible/not-found/deferred/rejected outcomes are explicit. Source/evidence reads retain live information filtering; privileged verifier inputs never return. Response defaults are ten items, maximum fifty/65,536 bytes; smaller caller byte bound can narrow.

Knowledge retains original time/scope/provenance/confidence, separate from executable code. Corrections append versions. Portable declaration alone grants no promotion. Domain records use adapter schemas; locations/handles cannot become generic facts.

Mutations durably bind run/tool/mutation key to canonical request and retained result before acknowledgement. Matching historical retry returns same knowledge/proposal/current outcome, changed content conflicts; missing key needs current authority. Retired run cannot forget keys then admit duplicates.

Accepted proposal and new immutable snapshot commit atomically. Deferred proposal keeps identity when re-evaluated. Eligible trusted gate needs no human approval, but sealed comparison defers publication and keeps arms isolated. Acceptance affects future snapshot selection, never current activation or retrieval scope.

## Warm startup requirement

Broader startup bundle is exact model-authored selection with applicability, dependencies/cards, compatibility, provenance and evidence, distinct from delivered named snapshot load. Unselected source stays selective.

Validate model/snapshot/hash, current task/profile applicability, capabilities, quarantine/security revocation and information scope. Cache reuse requires matching source/runtime/isolation/adapter/profile/schema/capability identities. Missing/rejected entries stay visible, never silent substitution/empty warm library or handwritten fallback.

Eligible versions may activate without source regeneration/repeated qualified tactical trials; zero strategic authoring is possible. Activation still needs current running state/fresh observations/ordinary lease. Inherited evidence is not current-run useful behavior.

Record hydration/cache/validation/activation, actual requests/available attempts, retrieval, total time and first confirmed effect equally for cold/warm. Frozen snapshot cannot override safety, revalidation cannot relabel historical profile evidence, and source restore does not rewind the world.
