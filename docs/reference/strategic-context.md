# Strategic context and retained evidence

Each actual SDK stream invocation, including tool continuations, receives run-owned context outside the disposable Agent. This is bounded reference reconstruction, not saved conversation, gameplay continuation or chain of thought.

## Request bounds and priorities

Serialized UTF-8 supplement: 32 KiB total. Whole compatible source plus reuse metadata shares 18 KiB; retained help has a 24-KiB ceiling, **not additive reservations**. Mandatory safety/no-replay references and reserved recent authored events precede optional source/help/old receipt detail. Explicit omissions retain recovery references.

Requested executable/temporal-view/resident/native invocation mechanics precede native action alternatives, other prose, adapter metadata and full observation/read/result schemas. Invocation fields remain separate from embedded result schemas. Top-level action alternatives remain whole: alternatives beyond the 6-KiB section bound omit rather than fragment. Other large reference sections split at schema/property boundaries.

Whole source is included or explicitly omitted, never an executable fragment. Help remains partial and directs re-requesting its current topic. Contracts supplement bounded current observations, tool pairs and feedback rather than replacing them.

Default cognition reconstructs through readonly canonical/projection locations. Embedded callers retain an owned context child. Each job pins a snapshot and original monotonic deadline within five seconds. Assembly stages checkpoint; only current successful unexpired settlement commits it. Failure preserves previous checkpoint/ordered operations; forced loss explicitly marks uncertain uncommitted custody. Cancellation joins process/pipes; no fallback reconstruction.

Before use, recheck request/run/generation/role/phase/profile/scope/deadline. Compatible readonly help survives tool-role/root-prose changes without preserving tool authority. Source compatibility uses executable/API/adapter/profile, not provider transport or prompt wording.

## Notes, history and uncertainty

Program progress/results may retain bounded model-authored subgoal, worksite, requirements/recovery notes and up to four explicitly returned positions. Cards are not current subgoals. Current resources/targets come from fresh observations.

Worksite means established or deliberately relocated observed task site; omitting it while travelling retains it. Temporary recovery position has its own label. Session/life/boot/space changes clear dynamic notes; explicit worksite/subgoal history can remain historical with provenance. Task/world/fresh-run change clears retained experience.

Selected source may include exact named/ordinal historical invocation arguments and outcomes. They are sanitized examples, not restored current arguments/targets or a recommendation to repeat blocked/unknown work.

Up to eight unresolved no-replay references persist separately from latest failure, with original scope/containment and omission counts. Fresh observation/containment cannot prove an old unknown never happened. They may survive life/session changes inside retained scope without regaining authority.

If a child failed but its containing root succeeded, an outcome wake does not force recovery role solely for that child. Preserve failure and unknown references. Unowned failures/unsuccessful containing roots still select recovery. Root success is not whole-task verification.

Durable Store events reconstruct supported references beyond one event page after Agent recreation or Store reopen. Restart still closes interrupted runs; no worker, stack, world checkpoint or target handle is restored.

## Observation and diagnostics

Strategic observe omits known host lifecycle identities from structured gameplay while retaining authorized gameplay/target/freshness/death reason. Separate image host-selection scope is explicitly unsynchronized and proves no capture-time life/camera/space correspondence. Native/SDK observation and isolated guard inputs retain their own contracts.

Typed evidence projections preserve argument/result and trace/event JSON subject to whole-record omissions. Arbitrary user JSON is not recursively stripped merely by key name. Names/versions/execution ordinals and event references remain distinct.

SDK diagnostic/preassembly copies replace image parts with image-reference MIME/base64-length/SHA-256 metadata. Text/tool details remain. This avoids duplicate PNG metadata payloads without changing actual SDK content or authoritative final recorded context, whose exact private image bytes remain retained when recording.

Cognition boundary errors use fixed categories for overlap, expiry, settlement and pre-fetch expiry without tool arguments, resolver context or arbitrary peer exceptions. They distinguish boundaries, not provider fault or model inability, and never renew admission.
